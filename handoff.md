# AWVM redesign — plan and progress

Goal: make `crates/awvm` the single rules engine behind the client, server, and
replay viewer, while staying a conformant implementation of `spec/`.

Three requirements driving it:

1. Supplant the existing awbrn game/server rules code (Bevy-agnostic core, or
   feature-flagged where that is not practical).
2. An adapter from the AWBW replay format to AWVM, so one viewer can step
   through either a replay or a spec fixture.
3. Stay spec-conformant throughout.

The 384 conformance assertions over `spec/fixtures/**` are the invariant for
every phase.

## Decisions taken

- **Modules, not crates, until phase 5.** Phases 1–4 move types constantly and
  cross-crate churn buys nothing; the generated tables are ~625 entries, far
  from a compile-time problem. Split only when there is a second consumer and
  the boundaries have stopped moving. The invariant to defend is the one in
  `crates/awvm/Cargo.toml` — no Bevy, no ECS, no replay — not the crate count.
- **Follow the repo's codegen convention.** No `build.rs` exists anywhere in
  the workspace. Convention is an `xtask-*` member, a `cargo xtask-…` alias in
  `.cargo/config.toml`, output checked in under `src/generated/` with a
  `// This file is @generated by …` header. Follow it.
- **One deviation: add a staleness gate.** Existing generated content has no
  CI check; drift there is cosmetic. A stale ruleset table is a silent
  correctness bug in a conformance claim, so `xtask-ruleset --check` belongs in
  the awvm CI job.
- **In-process conformance goes through the JSONL handler, not around it.**
  The test backend serializes to a string and calls the same `handle()` the
  subprocess adapter uses, so the in-process path cannot drift from what
  external implementations see.

## Phases

### Phase 0 — make the safety net load-bearing locally · DONE

`cargo test -p awvm` currently runs 82 of 306 fixtures from hand-maintained
`include_str!` lists. CI runs the full corpus in a separate step, so a broken
commander rule or every fog projection passes locally and fails in CI. Fix that
before touching semantics.

- [x] **0a** Move the JSONL request handler out of `bin/awvm-jsonl.rs` into
      `src/protocol.rs`; binary becomes a stdin/stdout loop.
- [x] **0b** Move case playback out of `bin/awvm-conformance.rs` into
      `src/conformance.rs`, parameterized over a `Peer` trait. `Subprocess` is
      the existing transport; `InProcess` calls `protocol::handle`. The
      existing `Peer::exchange(Value) -> Result<Value, String>` is already the
      single seam every request goes through.
- [x] **0c** `tests/conformance.rs` walking `spec/fixtures/**` with `InProcess`
      — 306 fixtures in `cargo test`, no list to maintain.
- [x] **0d** Delete the 655 lines of now-redundant fixture-replay tests from
      `transition.rs` (of 1,412 test lines; the other 757 are genuine unit
      tests and stay).
- [x] **0e** Golden snapshots of `observe` / `observe_events` across the whole
      corpus, captured from the current implementation and committed **before**
      any refactor. This is the phase-2 safety net: only 7% of fixtures assert
      observations today, so conformance alone will not catch the typed-`Event`
      migration breaking projection.
- [x] **0f** `mise` task for Rust tests (none exists) and a bench harness on
      `execute` so the phase-1 speedup cannot silently regress.

**Gate: met.**

| Before | After |
| --- | --- |
| 82 fixtures in `cargo test` | 306, discovered from disk |
| `transition.rs` 6,516 lines | 5,861 (−655 redundant test lines) |
| Observation projections asserted | 1,222 observations + 653 observed-event sets, all digested |
| Rust test task in `mise` | `test`, `test:rust`, `test:awvm` |
| `execute` benchmark | `awvm-execute` in `crates/bench` |

Files: `src/protocol.rs`, `src/conformance.rs`, `tests/conformance.rs`,
`tests/observations.rs`, `tests/goldens/` (752 KB),
`crates/bench/src/benchmarks/awvm.rs`.

`.github/workflows/ci.yml` needs no change — the awvm job already runs
`cargo test --locked -p awvm --all-targets`, which now includes both new test
files.

**The goldens were verified to fail.** Renaming the observed event
`movement-stopped` to `movement-halted` — a real change to the observation wire
format — leaves all 384 conformance assertions passing, and fails both golden
tests, with the detail golden naming `fog/non-fog-hidden-blocker.json`. That is
exactly the regression class phase 2 risks, and nothing before phase 0 caught
it.

Observation output was checked to be deterministic across processes (three
separate runs, identical digests) before the goldens were committed, so
`HashMap` seeding cannot make this suite flaky.

The `awvm-execute` bench reproduces the recorded baseline within noise
(283.8 / 535.0 / 1375.1 µs against 282.0 / 538.7 / 1363.4), independently
confirming the phase-1 target.

### Phase 1 — generate the ruleset

Split the performance win from the type migration so a problem in either half
does not block the other.

- [ ] **1a** `crates/xtask-ruleset` generating `crates/awvm/src/generated/` from
      `spec/rulesets/awbw/2026-07-10/**`: `#[repr(u8)]` enums for unit kind,
      terrain, commander, movement class, domain, fire mode, weather; dense
      tables (`DAMAGE: [[Option<u8>; 25]; 25]`, movement costs, capabilities).
      Nothing uses it yet. Test asserts the generated tables round-trip against
      the JSON they came from.
- [ ] **1b** Accessors taking the *existing* string types
      (`fn unit_profile(kind: &UnitKindId) -> Option<&'static UnitProfile>`).
      Replace all 45 `include_str!` sites. Banks the whole ~100× win without
      changing a single type signature elsewhere.
- [ ] **1c** Migrate the model to the enums — `UnitKindId(String)` →
      `UnitKind`, etc. `awbrn_types::Unit` already has exactly the 25 variants
      `units.json` defines, in the same order.
- [ ] **1d** Delete `awbrn-server`'s hand-written `PRIMARY_DAMAGE` /
      `SECONDARY_DAMAGE` const arrays in favour of the generated tables.
- [ ] **1e** `--check` mode wired into the awvm CI job.

**Gate:** conformance green; `execute` median under 10 µs; one damage matrix in
the workspace.

### Phase 2 — type the boundary values

`Violation` first: leaf values, constructed in `transition.rs`, never consumed
inside the crate — a one-sided change and a warm-up for the serde shape work.
`Event` second: two-sided, and the goldens from 0e are what make it safe.

- [ ] **2a** `Violation` enum, `#[serde(tag = "code", rename_all = "SCREAMING_SNAKE_CASE")]` — 127 sites.
- [ ] **2b** `Event` enum, 36 variants, `#[serde(tag = "type", rename_all = "kebab-case")]`.
- [ ] **2c** `observe_events` becomes an exhaustive match. The two
      spec-mandated omissions (`attack-resolved`, `random-outcome` — see
      `spec/model/observation.md:337`) become explicit arms carrying the
      citation. `ObserveError::InvalidEvent` is deleted. Note
      `draw-offer-changed` is handled but never emitted — no draw-offer command
      exists yet.
- [ ] **2d** `RandomToken` + `RandomTape` cursor; the hand-written
      `random_consumed: 2 / 4 / if counter.is_some() {4} else {2}` literals go.

**Gate:** byte-identical JSON on all 306 fixtures *and* unchanged observation
goldens. This phase must be invisible on the wire.

### Phase 3 — fix the model's representation leaks

- [ ] **3a** `Pos { x: u8, y: u8 }` and a flat board with a bounds-safe
      accessor — removes 61 `tiles[position[1]][position[0]]` inverted-index
      sites and 68 raw `position[0]`/`position[1]` uses.
- [ ] **3b** `TileOwner { NotOwnable, Neutral, Owned(PlayerIdx) }` replacing
      `Option<Option<PlayerId>>` and its custom deserializer.
- [ ] **3c** `PlayerIdx` / `UnitStore` with O(1) lookup, replacing 53 linear
      `units.iter().find/position/any` scans and 27 over `players`. String ids
      only at the wire edge.

**Gate:** conformance green; no raw `[usize; 2]` indexing left in semantics.

### Phase 4 — decompose the reducer

Two commits, in this order. Interleaved, it is an unreviewable 5,000-line diff
where a behaviour change hides inside a move.

- [ ] **4a** Move only: split `transition.rs` into `semantics/*.rs` mirroring
      the 19 documents in `spec/semantics/`. Zero edits except `use`
      statements.
- [ ] **4b** Then change: `ActiveTurn` / `MovedUnit` proof-carrying types.
      `ActiveTurn::open` does the ruleset/match/phase/actor checks once;
      `turn.plan_move` is the only source of a `MovedUnit`, so a reducer cannot
      skip path validation the way `execute_move_capture` and
      `execute_move_join` currently do (each holds a full verbatim copy of
      `validate_movement_prefix`; six more restate its opening guards).
- [ ] **4c** Direct unit tests at the newly reachable seams — capture, join,
      combat resolution — where fixtures alone are coarse. This is the real fix
      for `combat::damage` being pure and well-tested while the 680 lines that
      compute its arguments are reachable only through `execute`.

**Gate:** conformance green; no production function over ~200 lines; every
semantics module names its normative document.

### Phase 5 — adapt, then supplant

- [ ] **5a** `awvm-awbw`: `awbw_replay::Action` → `(Command, Vec<RandomToken>)`.
      Variants map nearly 1:1 (Fire → MoveAttack{Unit}, AttackSeam →
      MoveAttack{Tile}, Capt → MoveCapture, Build → ProduceUnit, End →
      EndTurn, …).
- [ ] **5b** Differential harness over archived replays. AWVM consumes random
      tokens rather than rolling them, and replays *record* outcomes, so a
      replay is a token tape and `execute` must reproduce the recorded game.
      Every archived replay becomes a conformance case.
- [ ] **5c** `Event` → ECS translation; port the replay viewer, then the live
      client. `State` as a Bevy `Resource`; ECS components stay the
      *presentation* model.
- [ ] **5d** Retire `awbrn-server/{validate,apply,damage}.rs`,
      `awbrn-game/replay/commands.rs`,
      `awbrn-client/modes/replay/commands.rs`, and three of the four fog
      implementations (`awvm::semantic::AwbwVisibility` survives).

**Gate:** one viewer stepping fixtures and replays through the same reducer;
archived replays reproducing to their recorded end states.

## Known risks

- **Revisionability vs. generated tables.** The spec is explicitly versioned
  and AWVM is meant to support multiple ruleset revisions. Generating one
  revision into `const` arrays is the fast path; a runtime loader must stay for
  others, but no second revision exists, so that path is untested by
  construction. Build it in phase 1 anyway.
- **Phase 2 can break invisibly.** Serde derives reproducing the exact current
  JSON — field-order insignificance, `skip_serializing_if`, nested
  `ObservedUnitRef` shapes — is fiddly, and fixtures only assert 7% of
  observations. The 0e goldens are what make this gate real.
- **Replay divergences are ambiguous** between AWVM bug, spec defect, and
  adapter bug. Start on fog-off, no-power replays to isolate adapter bugs where
  AWVM is best covered; keep the differential suite advisory until the noise
  floor is known, or phase 5 stalls on triage.
- **`commander.rs` is not the problem.** It deserializes into real structs
  rather than poking at `Value`, and its 193 fixtures pass. It needs the
  caching fix and the enum swap, not a redesign.

## Notes for whoever picks this up

- **Regenerating goldens:** `AWVM_UPDATE_GOLDENS=1 cargo test -p awvm`. Only do
  this when a projection change is intended — the digest table is the phase-2
  gate, and regenerating it discards the evidence it exists to preserve.
- **Reading a digest change:** the detail set covers fog, concealment,
  visibility, and every fixture asserting observations (31 fixtures). For
  anything outside it,
  `AWVM_GOLDEN_DETAIL=<path substring> cargo test -p awvm --test observations`
  writes full JSON for the matching fixtures, which you then diff.
- **`InProcess` goes through `protocol::handle`**, serializing the request to a
  string first. That looks wasteful and is deliberate: it keeps the test path
  identical to what an external adapter exercises. Don't "optimize" it into a
  direct call to `transition::execute`.
- **`awvm-conformance` is not redundant** with `tests/conformance.rs`. The
  binary exists for *other* implementations of the spec; the test is how this
  one checks itself. Both share the playback logic in `src/conformance.rs`.
