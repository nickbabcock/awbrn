# AWVM redesign — plan and progress

Goal: make `crates/awvm` the single rules engine behind the client, server, and
replay viewer, while staying a conformant implementation of `spec/`.

Three requirements driving it:

1. Supplant the existing awbrn game/server rules code (Bevy-agnostic core, or
   feature-flagged where that is not practical).
2. An adapter from the AWBW replay format to AWVM, so one viewer can step
   through either a replay or a spec fixture.
3. Stay spec-conformant throughout.

The conformance assertions over `spec/fixtures/**` are the invariant for every
phase — 384 when this was written, 391 today.

## Decisions taken

- **Modules, not crates, until phase 5.** Phases 1–4 move types constantly and
  cross-crate churn buys nothing; the generated tables are ~625 entries, far
  from a compile-time problem. Split only when there is a second consumer and
  the boundaries have stopped moving. The invariant to defend is the one in
  `crates/awvm/Cargo.toml` — no Bevy, no ECS, no replay — not the crate count.
- **Follow the repo's codegen convention.** No `build.rs` exists anywhere in
  the workspace. Convention is an `xtask-*` member, a `cargo xtask-…` alias in
  `.cargo/config.toml`, output checked in under `src/generated/` with a
  `// This file is @generated by …` header. Follow it.
- **One deviation: add a staleness gate.** Existing generated content has no
  CI check; drift there is cosmetic. A stale ruleset table is a silent
  correctness bug in a conformance claim, so `xtask-ruleset --check` belongs in
  the awvm CI job.
- **In-process conformance goes through the JSONL handler, not around it.**
  The test backend serializes to a string and calls the same `handle()` the
  subprocess adapter uses, so the in-process path cannot drift from what
  external implementations see.

## Phases

### Phase 0 — make the safety net load-bearing locally · DONE

`cargo test -p awvm` currently runs 82 of 306 fixtures from hand-maintained
`include_str!` lists. CI runs the full corpus in a separate step, so a broken
commander rule or every fog projection passes locally and fails in CI. Fix that
before touching semantics.

- [x] **0a** Move the JSONL request handler out of `bin/awvm-jsonl.rs` into
      `src/protocol.rs`; binary becomes a stdin/stdout loop.
- [x] **0b** Move case playback out of `bin/awvm-conformance.rs` into
      `src/conformance.rs`, parameterized over a `Peer` trait. `Subprocess` is
      the existing transport; `InProcess` calls `protocol::handle`. The
      existing `Peer::exchange(Value) -> Result<Value, String>` is already the
      single seam every request goes through.
- [x] **0c** `tests/conformance.rs` walking `spec/fixtures/**` with `InProcess`
      — 306 fixtures in `cargo test`, no list to maintain.
- [x] **0d** Delete the 655 lines of now-redundant fixture-replay tests from
      `transition.rs` (of 1,412 test lines; the other 757 are genuine unit
      tests and stay).
- [x] **0e** Golden snapshots of `observe` / `observe_events` across the whole
      corpus, captured from the current implementation and committed **before**
      any refactor. This is the phase-2 safety net: only 7% of fixtures assert
      observations today, so conformance alone will not catch the typed-`Event`
      migration breaking projection.
- [x] **0f** `mise` task for Rust tests (none exists) and a bench harness on
      `execute` so the phase-1 speedup cannot silently regress.

**The generated tables were verified to fail.** Mutating one damage value and one
terrain's `defense_stars` in the checked-in file failed
`damage_matrices_match_weapons_json` and `terrain_profiles_match_terrain_json`
by name, and `--check` exited 1. Regenerating restored the file byte-for-byte.

1c made the ruleset's vocabulary the model's: `UnitKindId`, `TerrainId`,
`CommanderId` and `WeatherKind` are now re-exports of the generated `#[repr(u8)]`

carries the specification's own identifier as its serde name — but an identifier
outside the ruleset now fails to decode. `spec/protocol.md` only pins that a
decoding failure is `status: "error"`, which it still is, and no fixture names an
identifier the ruleset lacks.

1d changed behaviour, deliberately. `awbrn-server`'s const arrays were labelled
"AWDS base damage table" and disagree with `spec/rulesets/awbw/2026-07-10/weapons.json`

the AWBW tables, which is the ruleset it claims to implement;

switch cannot silently revert. This gives `awvm` its first reverse dependency.

**Still open:** only the single lowered revision exists. `ruleset::supports()`
plus the existing `UnsupportedRuleset` gate refuses every other revision rather
than evaluating it against the wrong numbers, so nothing is silently wrong — but
the runtime loader the risks section calls for was not built, because no second
revision exists to load. See *Known risks*.

### Phase 2 — type the boundary values · DONE

`Violation` first: leaf values, constructed in `transition.rs`, never consumed
inside the crate — a one-sided change and a warm-up for the serde shape work.
`Event` second: two-sided, and the goldens from 0e are what make it safe.

- [x] **2a** `Violation` enum, `#[serde(tag = "code", rename_all = "SCREAMING_SNAKE_CASE")]` — 127 sites.
- [x] **2b** `Event` enum, 36 variants, `#[serde(tag = "type", rename_all = "kebab-case")]`.
- [x] **2c** `observe_events` becomes an exhaustive match. The two
      spec-mandated omissions (`attack-resolved`, `random-outcome` — see
      `spec/model/observation.md:337`) become explicit arms carrying the
      citation. `ObserveError::InvalidEvent` is deleted. Note
      `draw-offer-changed` is handled but never emitted — no draw-offer command
      exists yet.
- [x] **2d** `RandomToken` + `RandomTape` cursor; the hand-written
      `random_consumed: 2 / 4 / if counter.is_some() {4} else {2}` literals go.

**Gate: met.** 384 conformance assertions pass and both observation goldens are
byte-identical — the phase changed no wire output.

| `json!` sites in `transition.rs` | 150 → 0 outside tests |

| `Event` | `Value` → 35-variant enum, one per `event.schema.json` branch |

The speedup is a side effect, not a goal: building a typed struct is cheaper than
building a `serde_json::Value` tree, so events that are never observed no longer
pay to be serialized.

**Both safety nets were verified to fail.** Adding a field to `PathNonAdjacent`
failed conformance (the payload is asserted by 42 fixtures); making
`RandomTape::consumed` off by one failed it again (113 fixtures assert a non-zero
`random_consumed`). Note that `PATH_OUT_OF_BOUNDS`, `PATH_ORIGIN_MISMATCH`,
`PATH_OCCUPIED`, `WRONG_PHASE`, `MATCH_FINISHED`, `INSUFFICIENT_POWER` and
`AUTHORITY_REQUIRED` have **no fixture at all** — mutating one of those is not
caught, and they are worth fixtures before anyone leans on this net further.

Three things worth knowing:

* **`AttackTarget` was duplicated.** `transition::AttackTarget` (the target a
  command names) and the event's target were structurally identical types
  declared separately. They are now one type, so a command and the event it
  produces cannot describe the same target differently.
* **`ObserveError::InvalidEvent` split in two.** Most of its 11 sites were
  decoding an untyped event and became unreachable. The two that survive are a
  genuine disagreement between the separately-supplied state and events, and are
  now `ObserveError::UnknownUnit(UnitId)`. No fixture asserts either message.
* **A pre-existing defect was preserved, not fixed.** A malformed *combat* random
  tape reports `UNSUPPORTED_COMMAND`, while a malformed *weather* tape reports
  the execution failure `spec/model/violations.md` prescribes for "missing,
  wrong-type, or out-of-domain random input". Both should be the latter. Fixing
  it would have made this phase visible on the wire, so `transition::draw`
  carries the citation and the discrepancy instead. **Fix it in a later phase,
  with a fixture that pins the corrected class.**

### Phase 3 — fix the model's representation leaks · DONE

- [x] **3a** `Pos { x: u8, y: u8 }` and a flat board with a bounds-safe
      accessor — removes 61 `tiles[position[1]][position[0]]` inverted-index
      sites and 68 raw `position[0]`/`position[1]` uses.
- [x] **3b** `TileOwner { NotOwnable, Neutral, Owned(PlayerIdx) }` replacing
      `Option<Option<PlayerId>>` and its custom deserializer.
- [x] **3c** `PlayerIdx` / `UnitStore` with O(1) lookup, replacing 53 linear
      `units.iter().find/position/any` scans and 27 over `players`. String ids
      only at the wire edge.

**Gate: met.** 384 conformance assertions pass, observation goldens unchanged,
and the only code that turns a coordinate into an offset is inside `Board` and
`ObservedBoard` themselves.

| Before | After |
| --- | --- |
| `Position = [usize; 2]` | `Pos { x: u8, y: u8 }`, `[x, y]` on the wire |
| `tiles[p[1]][p[0]]` inversions | 61 → 0 outside `Board` |
| Raw `position[0]` / `position[1]` | 114 → 0 |
| `Board.tiles: Vec<Vec<Tile>>` | flat row-major, rectangle checked once at decode |
| `Option<Option<PlayerId>>` + custom deserializer | `TileOwner { NotOwnable, Neutral, Owned }` |
| Unit lookup | 54 linear `iter().find/position/any` on id → `get`/`index_of`/`contains` |
| Player lookup | 27 roster scans → `player_index` / `find_player` / `PlayerIdx` |
| `execute` medians | 1.30/2.08/3.38/1.26 µs → 1.40/2.17/3.62/1.30 µs |

**`execute` got 3–7% slower, and that is the honest result.** `UnitStore` carries
an id→index `HashMap`, and `execute` clones the whole state per command, so at
fixture scale — two to four units — cloning the index costs more than the O(1)
lookup saves. The trade inverts at real army sizes (an AWBW game runs 20–50
units), and everything stays far inside the 10 µs gate, but nobody should read
3c as a speed win. If this ever matters, the fix is to make the index cheaper to
clone, not to go back to scanning.

Three changes are visible outside the type system:

* **A coordinate beyond 255 no longer decodes.** `Pos` is a byte pair, so
  `[256, 0]` is now a decoding failure instead of a value that reaches
  validation and comes back `PATH_OUT_OF_BOUNDS`. No board approaches this and
  no fixture covers it — `PATH_OUT_OF_BOUNDS` has no fixture at all — but the
  error class did change. `a_coordinate_beyond_every_board_fails_to_decode`
  pins the new behaviour. **The specification puts no upper bound on a
  coordinate; if that is deliberate, this needs `u16` and a fixture.**
* **A ragged board no longer decodes.** `ObserveError::InvalidBoardShape` is
  gone, because the rectangle is checked while decoding. That is strictly safer:
  the old check lived only in `observe`, so a ragged board reaching `execute`
  would have panicked on a short row. Nothing pinned the old error.
* **Duplicate unit ids no longer decode.** `UnitStore` needs unique ids for its
  index to be a function, so it rejects a state that repeats one. Previously
  such a state decoded and the reducer silently operated on whichever unit came
  first.

`Board` and `UnitStore` keep the wire shapes exactly — nested rows and a plain
array — through hand-written serde impls, each pinned by a round-trip test.

### Phase 4 — decompose the reducer · DONE

Two commits, in this order. Interleaved, it is an unreviewable 5,000-line diff
where a behaviour change hides inside a move.

- [x] **4a** Move only: split `transition.rs` into `semantics/*.rs` mirroring
      the 19 documents in `spec/semantics/`. Zero edits except `use`
      statements.
- [x] **4b** Then change: `ActiveTurn` / `MovedUnit` proof-carrying types.
      `ActiveTurn::open` does the ruleset/match/phase/actor checks once;
      `turn.plan_move` is the only source of a `MovedUnit`, so a reducer cannot
      skip path validation the way `execute_move_capture` and
      `execute_move_join` currently do (each holds a full verbatim copy of
      `validate_movement_prefix`; six more restate its opening guards).
- [x] **4c** Direct unit tests at the newly reachable seams — capture, join,
      combat resolution — where fixtures alone are coarse. This is the real fix
      for `combat::damage` being pure and well-tested while the 680 lines that
      compute its arguments are reachable only through `execute`.

**Gate: met.** Conformance is green (384 assertions, goldens unchanged), every
module names its normative documents, and no production function in the reducer
exceeds 200 lines. The three that did are covered in *4d* below.

`semantic.rs`, not the reducer; `turn.md` and `turn-hooks.md` are both inside
one function. Modules are grouped by command family instead, and each names
every document it implements.

#### 4d — the three functions that were still over the gate

- [x] **4d** The oversized reducers cut down. Conformance green, both goldens
      byte-identical, `execute` unchanged within noise.

| Function | Before | After | Largest piece now |
| --- | --- | --- | --- |
| `attack::execute_stationary_attack` | 638 | 32 | `Engagement::open`, 101 |
| `turn::execute_turn_boundary` | 596 | 161 | `supply_from_adjacent_transports`, 74 |
| `attack::execute_tile_attack` | 205 | 167 | — |

**The 676-line function the previous entry named was `execute_stationary_attack`,
not `execute_move_attack`.** `execute_move_attack` is the 69-line movement
wrapper; the body lives in the stationary reducer it delegates to.

The predicted cut — convert the six closures, then lift the `counter_first`
branch — was right about the blocker and wrong about the size of the prize.
Converting them exposed that the branch was not one duplicated block but four:

* **`resolve_strike` replaced three copies.** Every strike scores the same way —
  the striker supplies the attack modifier and the two luck domains, the target
  supplies defense and terrain stars, and then the striker's commander modifies
  the target's stars. The initiating hit, the ordinary counter, and the
  counter-first preemptive each spelled out that same ~40-line sequence of two
  `effective_combat` calls plus `effective_enemy_terrain_stars`.
* **`apply_hit` replaced four copies.** Ammo spent, `attack-resolved`,
  `unit-damaged`, strike funds, power charge — in that order, every time.
* **`Engagement`** holds what validation established, so the two exchange orders
  are functions of it rather than branches that re-derive it.
  `counter_comes_first()` is now the only place the exchange order is decided.

`Combatant` construction went with them (`combatant()`), and the two separate
full-board scans for tower count and owned properties became one
(`combat_context()`), which is why the Colin case got ~4.5% faster.

`execute_turn_boundary` decomposed along the hook steps
`spec/semantics/turn-hooks.md` numbers, one function per step: `end_expired_power`
(2), `advance_weather` (3), `collect_income` (4), `supply_from_properties` /
`supply_from_adjacent_transports` / `supply_cargo` (5), `apply_fuel_upkeep` (6),
`crash_out_of_fuel` (7), `repair_on_properties` (8), `normalize_actions` (10),
plus `select_successor` and `swap_commanders` for the boundary itself. The
control loop that remains is the successor-selection loop
`spec/semantics/elimination.md` requires, and it now reads as the list of steps
the document specifies.

**A real defect fell out of the closure conversion.** `execute_tile_attack` built
its `CombatContext` with `funds: state.players[attacker_index].funds` — indexing
the *player* roster with the attacking *unit's* index. That is a different
player whenever the two orders disagree, and a panic whenever a player owns more
units than the match has players. Colin's super power is the only rule that
reads funds and no fixture fires it at a tile, so nothing caught it.
`spec/fixtures/combat/tile-colin-scop-funds.json` pins the corrected behaviour
normatively — it fires Colin's super power at a pipe seam with the attacker
listed second in `units` while its owner is listed first in `players`, so the
expected damage is 30 rather than the 15 the old expression produced. Verified
to fail against it.

One inert value changed spelling: a striker's `Side::terrain_stars`. The
formula in `combat::damage` reads defense and terrain stars only from the
target, so what the striker carried there never entered a result; the three
sites that filled it with the attacker's own stars now pass `0` and say why.

**Two mutations that the corpus does not catch, and should not be read as gaps:**
running `repair_on_properties` before `crash_out_of_fuel`, and deleting the
`day < 2` guard on fuel upkeep, both leave every test green. The first is
unobservable by construction — step 5 refills any unit standing on the owner's
repairing property, so a repair site can never also be a crash site — and the
second only differs on a turn-start reached while `day == 1`, which no fixture
does. Mutations that *are* observable were checked: drawing bad luck before good
fails four unit tests, and normalizing `immobilized` to `ready` fails
conformance.

### Phase 4.5 — make the observation side fit a consumer · DONE

`execute`, `observe` and `observe-events` are the three operations a viewer,
client and server all sit on. Phases 1–4 typed and sharpened the first; the other
two had not been looked at, and an API review before 5c found the projection
still returning untyped JSON and running 50× slower than the reducer it
describes.

- [x] **4.5a** `ObservedEvent`, a 10-variant enum, one per `oneOf` branch of
      `spec/schema/observed-event.schema.json`. `observe_events` returned
      `Vec<serde_json::Value>` built from 13 `json!` sites — the same untyped
      shape phase 2 removed from `Event` and `Violation`, on the output side.
- [x] **4.5b** `EventKind` and `PublicEventKind`. `Event::kind()` returned
      `&'static str` and served two different domains with it: the closed
      11-value `public-event.kind`, and the open `reason-id` an observed change
      is labelled with. `Event::reason()` now returns `ObservedReason`, which is
      either the reason the event declared or the kind it fell back to, and
      never spells a known reason as a fresh `String`.

**Both safety nets were verified to fail.** Renaming the observed event
`movement-stopped` fails the new schema-branch test, both goldens, and names
`fog/non-fog-hidden-blocker.json` — the same fixture the phase-0 check found.
Dropping the `teleporter` key from the hand-written `Tile` serialization fails

Four things worth knowing:

* **`occupancy_is_disclosed` lost half its definition.** It tested "the owner is
  an ally, or the unit is visible". The first disjunct was redundant — a
  viewpoint reports a unit of the viewing team as visible wherever it is, which
  is the same predicate — so it is now one call. It kept its name because the
  disclosure rule is worth naming.
* **The post-observation resolves the recipient's team from `state`, not
  `next_state`.** The event projection always did; only the discarded
  `observe(next_state)` call differed. A recipient who changed teams mid-command
  is not a transition the specification admits, and one absent from `next_state`
  is still rejected.
* **Sightings are resolved lazily.** A reducer builds a viewpoint to ask whether
  one tile is occupied by something it can see; in a match without fog or hidden
  units that answer never consults a sighting. Eager resolution cost `execute`
  14% on the movement case, and the `OnceCell` gave it back.
* **`Tile::shrink` is what keeps equality derivable.** Boxing gives `rare` two
  spellings for one state, and a derived `PartialEq` reads `None` and an
  allocated-but-empty block as different tiles even though they serialize to the
  same bytes. Every path that sets `rare` normalizes, so the derive stays
  correct — and `a_tile_that_loses_its_rare_state_equals_one_that_never_had_any`
  fails if `shrink` stops working. A hand-written `PartialEq` was tried first and
  reverted: it made the invariant moot but silently ignored any field added to
  `Tile` later, turning a loud wrong-inequality into a quiet wrong-equality.

**Still open, from the same review and deliberately not done here:** the
observation types are `Serialize`-only and `Command` is `Deserialize`-only, so a
*client* can decode neither an `Observation` nor encode a `Command` without
mirroring the types; `protocol::handle` parses every request line twice and
builds its response as a `Value` that the binary then serializes again;
`RulesetRef.revision` is a bare `String` and the supported-revision predicate
exists in two places (`ruleset::supports` and an inline compare in
`protocol.rs`); `PlayerId` is a heap `String` stored per unit, per owned tile
and per event; `ObservedBoard.tiles` is still the nested `Vec<Vec<_>>` phase 3
removed from `Board`; and `Command` repeats `player` across all 20 variants.

**Taken up in phase 4.6 below.** Four of the six landed; two — the inline
player id and the `Command { player, action }` pair — were built, measured, and
reverted for costing more than they returned.

**4.6f is the interesting one.** Holding `player` once means the flat wire shape
needs `#[serde(flatten)]`, and serde's flatten buffers the request map a second
time before the internal tag can be dispatched. Measured directly against an
equivalent flat enum: **929 ns versus 632 ns per command decode**, which showed
up as a 17–20% regression on three of the four `execute` cases — the benchmark
decodes a command per iteration, as the protocol does per request. Spending a
fifth of `execute` to avoid restating one field eighteen times is the wrong
trade, so `Command` keeps its flat shape, gains `Serialize`, and carries the
measurement in its doc comment. A hand-written `Deserialize` could have both;
it is ~120 lines of visitor that every new command has to be threaded through,
and it is not worth it until something else needs it.

**4.6e bought less than its premise suggested.** `string_id!` was moved onto

with everything else held fixed:

| --- | --- | --- |
| `execute` medians | 1.535 / 2.201 / 2.463 / 1.274 µs | 1.426 / 2.083 / 2.426 / 1.173 |
| `observe` / `observe_transition`, fog 20x20 | 21.19 / 25.59 µs | 21.06 / 25.02 |

1.5–8% on the reducer, 0–2% on the projection, 6% on a game-scale clone. The
allocations really do go — but a state clone is dominated by copying the board,
so removing one per unit and one per property moves a few percent, not a
multiple, and it does not improve with scale: that clone measurement is already
at real army size and shows the same 6% the fixture-scale ones do.

**Reverted**, because ~5% on `execute` does not earn `awvm` a dependency it did
not have. The measurement stands if someone wants to revisit it: the change is
two lines in `string_id!` plus a workspace entry, and `smol_str` is already in
the lock file transitively. Note the premise it rests on — that ids are what a
state clone spends its time on — is the part that turned out to be wrong, so a
future attempt should aim at `Tile` and the board, not at the identifiers.

**Two things worth knowing:**

* **`ObservedReason` decodes to the kind when the string is one.** The wire
  carries a single string and the type has two variants — a declared reason and
  the event-kind fallback — so a reader has to choose. It resolves an
  `EventKind` first, which is only harmless while the vocabularies are disjoint;
  `no_event_kind_is_also_a_reason` fails if they ever overlap.
* **`ResponseBody` is serialize-only, deliberately.** Three payloads report
  `status: "ok"`, so the tag does not identify the branch and there is nothing
  for a reader to dispatch on. A client decodes the payload for the operation it
  asked for.

`tests/wire.rs` is what makes 4.6a real rather than a set of derives: it takes
every command the corpus issues and every observation and observed-event set the
implementation projects from it, and requires encode and decode to be inverses.
That is 348 commands, 1,134 observations and 558 observed-event sets, using
the corpus for realistic values instead of hand-written ones.

## Known risks

- **Revisionability vs. generated tables.** The spec is explicitly versioned
  and AWVM is meant to support multiple ruleset revisions. Generating one
  revision into `const` arrays is the fast path; a runtime loader must stay for
  others, but no second revision exists, so that path is untested by
  construction. Build it in phase 1 anyway.

  **Not done in phase 1, and this is a deviation from the plan.** 1c made the
  ruleset's vocabulary the model's type — `UnitKind`, `Terrain`, `CommanderKind`
  are generated enums that a `serde` decode validates against *this* revision.
  A runtime loader would need those types to be open again, which would give
  back most of what 1b and 1c bought. Writing one against a hypothetical second
  revision would also be guessing at what varies between revisions: whether a
  revision may add a unit kind, or only retune numbers, decides whether the
  loader can reuse the generated vocabulary at all, and nothing answers that
  today. What exists instead is a refusal: `ruleset::supports()` gates on
  `(id, revision)` and anything else is rejected as `UNSUPPORTED_RULESET`, so a
  second revision fails loudly rather than being scored against the wrong
  numbers. **Decide this when the second revision lands, and let its actual diff
  against `2026-07-10` settle whether the vocabulary is shared or per-revision.**
- **Phase 2 can break invisibly.** Serde derives reproducing the exact current
  JSON — field-order insignificance, `skip_serializing_if`, nested
  `ObservedUnitRef` shapes — is fiddly, and fixtures only assert 7% of
  observations. The 0e goldens are what make this gate real.
- **Replay divergences are ambiguous** between AWVM bug, spec defect, and
  adapter bug. Start on fog-off, no-power replays to isolate adapter bugs where
  AWVM is best covered; keep the differential suite advisory until the noise
  floor is known, or phase 5 stalls on triage.
- **`commander.rs` is not the problem.** It deserializes into real structs
  rather than poking at `Value`, and its 193 fixtures pass. It needs the
  caching fix and the enum swap, not a redesign.

## Notes for whoever picks this up

- **Regenerating goldens:** `AWVM_UPDATE_GOLDENS=1 cargo test -p awvm`. Only do
  this when a projection change is intended — the digest table is the phase-2
  gate, and regenerating it discards the evidence it exists to preserve.
- **Reading a digest change:** the detail set covers fog, concealment,
  visibility, and every fixture asserting observations (31 fixtures). For
  anything outside it,
  `AWVM_GOLDEN_DETAIL=<path substring> cargo test -p awvm --test observations`
  writes full JSON for the matching fixtures, which you then diff.
- **`InProcess` goes through `protocol::handle`**, serializing the request to a
  string first. That looks wasteful and is deliberate: it keeps the test path
  identical to what an external adapter exercises. Don't "optimize" it into a
  direct call to `transition::execute`.
- **`awvm-conformance` is not redundant** with `tests/conformance.rs`. The
  binary exists for *other* implementations of the spec; the test is how this
  one checks itself. Both share the playback logic in `src/conformance.rs`.
